# HW3: 모방학습 (Imitation Learning)

ETH Zurich Robot Learning 2026 (Oier Mees) 과제 3을 독학으로 수행한 기록입니다.
SO-101 로봇팔 시뮬레이션(MuJoCo)에서 키보드 원격 조작으로 시연을 직접 수집하고,
Behavior Cloning, HG-DAgger, Goal-Conditioning(사실상 태스크 컨디셔닝)을 사용한 정책을 학습했습니다.

> 과제 정답 코드는 공개하지 않고, 실험 과정과 결과, 배운 점 위주로 정리했습니다.

## 설정

| 항목 | 내용 |
|---|---|
| 행동 공간 | 손끝 위치 변화량 (Δx, Δy, Δz) + 그리퍼 명령 → 관절 각도는 시뮬레이터의 IK가 계산 |
| 정책 | MLP + 액션 청킹 (상태 1개 → 미래 행동 16개 묶음 예측), MSE 손실 |
| 상태 (실습 1, 2) | 손끝 위치, 그리퍼, 큐브 위치, 장애물 위치 (10차원) |
| 학습 | AdamW, Cosine LR 스케줄, 200 에폭 |

행동 공간을 관절 각도가 아닌 손끝 변화량으로 고른 이유: 시연을 손끝 기준으로 조종했고,
관절 계산(IK)을 환경에 맡기면 정책이 배울 내용이 단순해지기 때문입니다.
action space를 관절각(joints)으로 두면, 정책이 IK 계산을 해서 관절각을 출력해야 하므로 좀더 무거워질 것 같아서 손끝값(ee)으로 설정했습니다.

## 실습 1: 행동 복제 (장애물 피해 큐브 옮기기)

<!-- 성공 롤아웃 GIF -->

| 버전 | 변경 | val loss | 성공률 (10회) |
|---|---|---|---|
| v1 | 시연 21개 (일관성 낮음), MLP 128×2 | 0.340 | 대부분 실패 |
| v2 | 시연 재수집 21개 (일관된 경로, 멈춤 최소화) | 0.303 | 30% |
| v3 | 모델 확대 MLP 256×3 (26K → 151K 파라미터) | 0.233 | 60% |

**진단 과정**

- **v1 실패: 큐브 앞에서 꼼지락거림.** Demonstration마다 일관성없게 조작했음. 가령, 큐브 위에서 미세 조정을 위해 꼼지락거렸는데 그게 에피소드(20개)마다 달랐음.
  loss는 MSE를 쓰다 보니까, 봉우리(mode) 평균내는 MSE 특성상 행동이 애매하게 바뀌어버렸음.
  
  → 정렬은 높은 곳에서 끝내고 수직으로만 내려가기, 큐브를 집은 후 바구니에 넣는 과정은 망설임없이 디귿자 궤적으로 한번에 집어넣는 시연 에피소드 20개를 만듬.
- **v2 → v3: train ≈ val(검증데이터 손실) 이면서 둘 다 높은 채로 평평.** 은닉층 뉴런수랑 MLP depth가 너무 작았음, 즉 모델이 너무 작아서 문제였던 것 같음.
  → 은닉층 뉴런수(d_model)를 128->256, depth는 2에서 3으로 모델을 살짝 더 키웠음.
- **남은 실패: 옮기는 도중 큐브를 떨어뜨림.** 데이터를 열어보니 그리퍼 닫기 명령값이
  시연마다 달랐음 (키 입력 횟수에 따라 −0.174 ~ 0.1). 키보드로 시연 데이터 수집할 때, 그리퍼 키를 내가 일관성있는 시간동안 안누르고 어떨 때는 살짝 집어서 넣은 게 문제같음.
  → 해결: 매번 끝까지 닫기. 세기보다 일관성이 중요.

## 실습 2: HG-DAgger (장애물 위치 이동)

장애물을 좌우 8cm씩 옮긴 환경(가운데 20%, 양옆 각 40%)에서 정책을 돌리고,
실패할 때 사람이 개입해 교정 데이터를 모은 뒤 원래 시연과 합쳐 재학습했습니다. (Dagger 말고 HG-DAgger)

**관찰**

- 실습 1 정책은 장애물이 옮겨지면 **시작하자마자** 아예 그냥 이상한 행동을 해버렸음. 원인은 두 가지:
  1. 분포 이동: 옮겨진 장애물을 한 번도 본 적 없음
  2. 정규화 폭발: 원래 시연에서 장애물 위치가 거의 고정이라 표준편차가 약 0.005.
     8cm 이동 시 정규화된 입력이 약 16이 되어, 정규화된 범위인 -1~1 근처값을 보다가 너무 큰 값을 봐버려서 정책이 완전 오류가 나버렸음.
- 옮겨진 배치에서는 ㄷ자 우회 경로가 막혀 **다른 경로(직진)** 가 필요.
  장애물 위치가 상태에 있으므로 MSE 정책도 두 경로를 구분해서 배울 수 있음.
- DAgger 7개 에피소드로는 옮겨진 배치를 학습시키기에 부족했음, 실습 1의 장애물 구조에서는 시연 20개 만들었는데 HG-DAgger는 2개의 다른 장애물 케이스를 각각 3,4개 정도를 만들어서, 데이터 양이 너무 적었음.

**배운 점**

- HG-DAgger를 직접 해봤는데, 계속 화면을 보면서 모니터링하는 게 너무 힘들었음. 비싼 이유를 직접 체감했음. 그리고
  시뮬레이션에서 언제 로봇이 비정상적 action을 시작하는 지는 내가 눈으로 알 수가 없었음, 즉 인간의 개입 시점 자체를 아는게 어려워보임을 직접 느꼈음.
- 학습 데이터에서 거의 변하지 않는 입력은, 테스트 때 조금만 바뀌어도 정책을 망가뜨릴 수 있음. 모방학습의 단점인 compounding error랑도 좀 연관됨을 느꼈음.
  본 적 없는 상태를 마주하니 이상한 action을 하고, 그게 누적되어서 아예 정책이 망가진 것 같음.

## 실습 3: 태스크 조건부 정책 (멀티큐브)

빨강, 초록, 파랑 큐브와 보관함 위치가 매 에피소드 무작위로 바뀌고,
지정된 색의 큐브를 보관함에 넣어야 합니다. 시연 30개 (색깔별 10개).

<!-- 성공 롤아웃 GIF -->

**정책 구조: 목표 큐브 위치를 먼저 골라 MLP에 넣기**

```
상태 (19) = 손끝(3), 그리퍼(1), 빨강/초록/파랑 큐브 위치(3×3), 목표 원핫(3), 보관함 위치(3) -> RGB cube pos랑 목표 원핫을 조합해서 tensor 다시 만들어야됨. (목표 큐브 위치 tensor)

목표 큐브 위치 = 원핫[0]·빨강 + 원핫[1]·초록 + 원핫[2]·파랑
MLP 입력 (10) = [손끝, 그리퍼, 목표 큐브 위치, 보관함 위치] : pytorch 코드에서 torch.cat으로 손끝, 그리퍼, 목표 큐브 위치, 보관함 위치를 엮었음.
```

19차원을 그대로 넣으면 정책이 "어느 큐브를 봐야 하는지"까지 30개 시연으로 배워야 합니다.
목표 큐브를 구조적으로 골라주면 문제가 "큐브 하나 옮기기"로 단순해집니다. (정책 가볍게 하기)
정규화된 원핫은 0/1이 아니므로 부호(> 0)로 다시 0/1로 복원했습니다.

과정 : 빨강 -> 초록 -> 파랑 큐브 한번씩 10번(총 30번) 시연데이터 수집을 진행하였습니다.

| 결과 | 값 |
|---|---|
| train / val loss | 0.37 / 0.43 |
| 성공률 (10회) | 50% (빨강 3, 초록 1, 파랑 1) |

과제 기준에서 50% 근처를 매우 우수한 성능으로 봅니다.
train과 val의 차이는 배치가 매번 무작위인 데 비해 시연이 30개뿐이라 생긴 것으로 판단합니다.

## 전체에서 배운 점

1) 데이터를 대충 찍다가, 일관성 있게 20개의 데이터를 찍었더니 validation loss(val loss)가 낮아짐 -> 데이터 품질이 중요함을 좀 느꼈음 (0.34 -> 0.30)
	**MSE** : ex) 큐브한테 가까이 가서 잘 찝으려고 꼼지락 대는게 에피소드마다 꼼지락 방향도 다르고 해서 일관된 데이터를 못모았음. **MSE**라서 일관성의 중요성이 더 심함. 얘는 평균값 내버리니까 할때마다 다르게 하면 이상한 값을 내버림. 그래서 할 때마다 일관성있게 데이터 모으는게 중요.
	**GMM, Diffusion, CVAE** : 일관성은 덜중요. 그래도 일관성은 중요함. 왜냐면 막 멈칫거리거나 움찔거리는 그런것조차 전부 봉우리(mode)로 배워서 그대로 따라함. (**강의 내용 기준**)
	그리고 데이터 5개가 다 똑같은 시연이면 5개를 학습한건데, 5개가 다 다른 행동한거면 사실상 각 토픽에 대해서는 1개의 데이터만으로 학습을 한거임.

2) 은닉층 뉴런 128, MLP depth 2 -> 은닉층 뉴런 256, MLP depth 3으로 바꾸니까 val loss가 0.30 -> 0.23까지 줄고 정확성도 10회 롤아웃 기준 30%->60%까지 오름 -> **모델 크기**도 학습에 중요한걸 좀 느꼈음

3) 처음 학습때 모았던 데이터 20개는 장애물 위치가 똑같았음. 그래서 장애물 위치가 달라진 경우에서는 rollout에서 로봇이 이상한 행동을 하기 시작했음.
	**정규화 문제** : state 안의 값들은 원래 학습 전에 숫자들을 정규화함, 장애물 위치 값도 마찬가지 (z-score 방식). 
	처음 시연데이터 모을때 장애물 위치는 거의 비슷 -> 장애물 평균이 대충 x평균은 -0.22, x standard deviation은 한 0.005(장애물 위치가 거의 동일)라고 할 때
	-> 새 평가에서 장애물이 한 8cm(0.08)정도 옮겨지면, (-0.14 - -0.22) / 0.005 = 16 -> -1~1 근처 값만 보다가 16의 state를 보니까 신경망이 본적이 없는 값에 당황을 해버림 -> 그냥 엉망 출력

4) 큐브 잡아서 옮기다가 떨구는 경우가 있었음
	시연마다의 그리퍼 명령 확인해보니까 꽉 집었을 때의 값이 다 달랐고, 평균적으로 약하게 쥐었음을 확인할 수 있었음.
5) DAgger 후 val loss가 올라갔는데. 이는 검증 데이터가 달라진 것이므로 무조건 나빠진 거라고 볼 수는 없음
6) **DAgger에서 느낀 점** : 사람이 계속 모니터링하는 것은 굉장히 힘들었음, 비싼 이유가 있다. 그리고 로봇이 어느 시점에서 정확히 잘못 action을 하기 시작하고, 그래서 사람이 정확히 어느 시점에서 개입해야 하는지 아는건 사실상 불가능에 가까움. 그냥 보통 감으로 **추가적으로 교정해주고 싶은 부분의 시작점**부터 사람이 개입하는 것이 일반적인 것 같음.
7) 학습 loss < 검증 데이터 loss => 보통 **학습데이터에 대한 overfitting**을 암시함. 그러므로 보통 두 loss가 거의 유사하게 나오는게 가장 깔끔한 구조. / train, val loss 둘다 비슷한데 높으면 보통 모델 크기 작아서 그럼.
